## AMB-01 — Shape of the Binance announcement catalog response for transport-level ID extraction

- Spec: S-1.7 M3-3, EC-8, DEC-45, section 15.
- Literal text: "the minimum mechanical parsing needed to extract the article ID / code / URL from the raw catalog response".
- Options: (a) collect every `id` / `code` / `url` key anywhere (would also pick up response status codes and catalog ids); (b) collect only from entries of `articles` lists.
- Classification: implementation clarification.
- Code now: `forward_store.extract_transport_id` reads only the entries of lists under an `articles` key (any depth), returns `code` (else `id`) and `url` as strings, de-duplicated in order; never titles, bodies or dates. The real shape is to be confirmed when the recorder is built (Task 18).

## AMB-03 — Numeric materiality threshold for a funding source conflict

- Spec: S-2.6 (Overlap), DEC-32.
- Literal text: "keys, rates and timestamps are compared. If they agree, archive provenance is kept. A material conflict is reported as a data-integrity blocker."
- Options: (a) any rate difference; (b) a tolerance. The spec gives no numeric materiality threshold.
- Classification: implementation clarification.
- Code now: `funding.merge` matches REST to archive keys within the frozen +-60 s tolerance; rates are parsed to float and conflict when `abs(archive - rest) > 1e-12` (`funding.RATE_ATOL`). Also an `IntegrityBlocker`: a REST record matching several archive records, two REST records mapping to the same archive settlement, or two records of one source within 60 s. On agreement the archive rate, timestamp and `source = "archive"` are kept, and a null `mark_at_settle` is filled from REST with `mark_source = "rest"` (S-4.6 first-tier mark; fills a null, overwrites nothing); REST rows with no archive key within 60 s fill the gap with `source = "rest"`. Kline conflicts (S-2.2 DEC-33) use exact equality of every value column after parsing.

## AMB-04 — Funding records outside any instance and undetermined nominal in the U3 gap test

- Spec: S-2.2, S-2.3 U3, S-2.6 (DEC-29/40/47, EC-9).
- Literal text: "funding records ... never cross an instance boundary"; "a gap exists when spacing > max(previous nominal interval, current nominal interval) + 60 s".
- Options: (a) records in a dormant interval (no instance) are treated as invalid; (b) they are excluded from annotation and never used. For `u3_gap` with an undetermined nominal: (a) treat as no gap; (b) use the known one; (c) fail closed.
- Classification: implementation clarification.
- Code now: `intervals.annotate` marks records with no instance as `in_instance=False`, `instance=None`, `reconciled=False`, `invalid=False`, `nominal_h` NA and `r8` NaN; they never serve as the previous record of an instance record. An invalid record keeps its timestamp as the spacing anchor for its successor but contributes the inherited previous nominal (never its own explicit/inferred value). `u3_gap` uses the known nominal when only one is undetermined and returns True (gap, fail closed) when both are undetermined.

Additional interpretations under AMB-04 (all implementation clarifications):
- `last_trade_ts` is the close (open + 15 min) of the last volume > 0 15m bar; `end_known_at = last_trade_ts + 7*24 h` (EC-1).
- A trailing dormancy ends the last instance only when 7 complete UTC calendar days lie between the last active day and `data_end_ns`.
- Instance membership is `first_bar_ts <= ts < last_trade_ts` (end-exclusive): a funding record exactly at the final bar close (e.g. a settlement at the cessation time) falls outside the instance and is never used. `instance_of`/`assign` are retrospective and must not be used as-of t; `current_instance` is the PIT function.
- A record with an explicit interval is reconciled if its spacing equals the previous nominal OR its own explicit interval (spec-literal). So explicit 4 with spacing 8 = previous nominal 8 is reconciled with nominal 4 (no transition flag; flags apply to records without an explicit field).
- `annotate` on a multi-symbol frame requires a dict covering every symbol and a unique index (ValueError otherwise).

## AMB-05 — USDⓈ-M context phrase list, scheduled-time mapping and the 72 h HALT test (Task 6)

- Spec: S-2.5 (DEC-37, DEC-40), S-5.4.
- Literal text: "the notice unambiguously refers to Binance USDⓈ-M futures / perpetuals, or to the exact relevant derivatives product"; "a timestamp ... explicitly maps that timestamp to that exact contract"; "not HALTED at any time in [scheduled_delist_ts, scheduled_delist_ts + 72 h]".
- Options: the spec gives no phrase list, no definition of "explicitly maps", and no sampling grid for "any time".
- Classification: implementation clarification.
- Code now (`luna/v7/data/notices.py`):
  - Symbol: whole token = bounded by non-alphanumeric characters, case-sensitive, on the raw text.
  - Context (after NFKC + casefold, so "USDⓈ-M" = "usds-m"): `USDM_PHRASES` = {"usds-m", "usdt-margined", "usds-margined"}, or both "perpetual contract" and "futures" present. Any "coin-m" / "coin-margined" mention makes the context ambiguous -> no match. A notice meeting neither condition is no match.
  - `scheduled_ts` only parses `YYYY-MM-DD HH:MM[:SS] [AM|PM] (UTC)`. Candidates are taken only from sentences containing the symbol token (sentences split at `.;!?` + whitespace or newline): a sentence with one timestamp maps it to every symbol it names (so "A, B and C ... at T" gives T to each); a sentence with several timestamps maps only via an ordered list "A and B ... T1 and T2 respectively" with equal counts and the symbol listed once. Exactly one distinct candidate overall, else None. 12-hour clocks with an hour outside 1-12 make the result None.

Each in-force delisting version is evaluated by itself (own scheduled time and known_at); U6 is active while any in-force version has not auto-cleared; a matched postponement/cancellation clears all earlier in-force versions.
  - Terminal classification (`terminal.py`): the R12 `source` must be in `EXACT_SOURCES` = {"official_historical", "official_formula_exact"}; a symbol token continued by `_` or by `-`/`.` plus an alphanumeric (e.g. `XXXUSDT_240628`) is no match; seconds in timestamps are parsed exactly; an R12 row must carry `contract_instance_id` = `<symbol>#<instance idx>` and the venue (default binance) or `classify` raises; a notice without `known_at` gives class C; class A also needs `settlement_ts` == the notice's scheduled time (otherwise B).

- Spec: §9 (feature table, side adjustment, r8, instance boundary, linear / LightGBM preprocessing), S-2.2, S-2.6, S-4.3-S-4.5, S-5.2, S-10.4, L1, L5.

Flagged for review (could change model inputs, not the economics of labels/books): (b) F14 ratio units; (c) F12 ranking all three F5 values.
- Code now (luna/v7/features.py; t = decision time, L = last full hour <= t - 1 min, W = window):
  - Common: every input row has known_at <= t - 1 min and belongs to the current instance (open_ts / funding_ts >= first_bar_ts; funding via universe.pit_funding, refactored out of the U3/U7 code; no upper bound before end_known_at). No current instance -> every symbol feature NaN (F11 BTC/market values still computed). Missing input -> NaN.
  - side = s (+1 / -1). (Scope of the side adjustment: see AMB-09.) CARRY_DIRECTION (x -s) = F1 (4), F3 (3), F5 (3), F11 cross-sectional median FL1 and share FL1 > 0, F12 (6 ranks). Rule: a feature is carry-direction iff it is a signed funding / premium level or change of the candidate, the market funding direction, or a rank of such a value. Not adjusted: F2, F4, F6, F8, F9, F10 (price momentum), F11 BTC return / vol, F13, F14.
  - F1: FL_W = mean r8 of valid records with funding_ts in (t - W, t], W = 24 h, 72 h, 168 h, 720 h (at 00:05 with 8 h funding: 3 / 9 / 21 / 90 records). Invalid records (S-2.6) and NaN r8 are missing (dropped).
  - F2: share of the 30 d valid records with sign(r8) == sign(FL1); lag-1 autocorrelation = Pearson corr of consecutive valid records in the 30 d window (invalid records dropped, not breaking pairs: a lag-1 pair can bridge a dropped invalid record, i.e. span two nominal intervals); NaN if either side is constant.
  - F3: OLS slope of r8 on time in days over the 7 d valid records (NaN if < 2 distinct times); FL1 - FL7; (FL1 - FL3) - (FL3 - FL7).

Means over bars whose close (open + 15 min) is in (t - 8 h, t - 1 min] (32 bars) and (t - 24 h, ...]; "last premium close" = the latest such value with close in the 24 h window (else NaN).

  - F8: log of the U2 median daily quote volume over the 30 UTC days fully ended before t (universe.median_daily_quote_volume; empty day = 0; median <= 0 -> NaN); Amihud = mean over the 7 UTC days fully ended before t of |C(day end) / C(previous day end) - 1| / daily quote volume (C = close of the 15m bar closing at 00:00; days with a missing close or zero volume skipped); log(sum n_trades of those 7 days / 7) (NaN if 0 or no n_trades column).   - F12: percentile rank (average rank of ties / n) of the candidate's FL1, FL7, FL30, and each of the three F5 values within {finite values of eligible symbols} with the candidate's own value included (it is one of them when eligible; a non-eligible symbol is ranked against the eligible set plus itself). Six columns.
  - F13: rvol_7d / (|FL7| * 3 * 365) and std(30 d valid r8, ddof = 1) / |FL30|, each min(., 1e4); denominator 0 with numerator > 0 -> 1e4; 0 / 0 or a missing input -> NaN.
  - F14: cost = 2 * taker (S-4.3: labels are taker, 0.0005) + 2 * h(t) + 2 * slip (0.0002), reported in bps; ratio = (|FL7| * 3 * h / 24) / cost with both in fractions (unitless; the literal bps denominator would only rescale by 1e4).   - Preprocessor (linear models): fit(X, decision_ts, fold) raises LeakageError if any decision_ts is outside T_fit = [fold.tr[0], fold.sel[1]) (T_cal, test, pre-D0); the S-10.3 purge of the sample set is the fold builder's job (features use no labels). ## AMB-09 - Scope of the §9 side adjustment: directional price features (Task 9)

- Spec: §9 "Side adjustment. Carry-direction features are multiplied by -s, so that positive means favourable to the candidate's side. A side indicator is included."
- Literal text: only "carry-direction" features are multiplied by -s.
- Options: (A, literal) side-adjust only funding / premium (carry-direction) features; F10 momentum (24 h / 7 d / 30 d returns, 7 d residual return) and F11 BTC 30 d return stay un-adjusted. (B) side-adjust every signed directional feature (x +s for price returns so positive = favourable to the side, or equivalently x -s under a sign convention), which is what "positive means favourable to the candidate's side" suggests for price direction.
- Consequence: both sides are fitted by one model per horizon. Under (A) a linear model sees the same F10 / F11-BTC value for the long and the short candidate of a symbol; its coefficient therefore pushes both sides' scores in the same direction, and the additive side indicator cannot undo that (it only shifts the intercept by side; it cannot flip the sign of a slope). A linear model thus cannot use directional price information (e.g. "positive momentum favours longs") at all. LightGBM can (via splits on side), so (A) also tilts the A2-vs-A3 comparison.
- Classification: **normative amendment required - user decision.** Whether every signed directional feature is side-adjusted is a methodology choice the spec text does not make; it is not an implementation detail.
- Code now (luna/v7/features.py CARRY_DIRECTION): the literal reading (A) - controller ruling, fix round 1 of Task 9 - until the user decides. Switching to (B) is a one-line change of CARRY_DIRECTION plus a sign convention for price returns.

## AMB-10 - Leg-label edge rules: data gap, BTC hedge exit, terminal reach, window end, funding window (Task 10)

Code: the bar's OPEN (P is an open price) replaces the missing reference price; the fill time stays tau (funding window and BTC timing unchanged); the bar must open in [tau, tau + 60 min], lie in the same instance (E10, never after `last_trade_ts`) and before the window end, and have a finite open > 0 (unusable bars are skipped, never priced). Flagged `entry_gap_price` / `exit_gap_price` (`btc_*` for B). Classification: implementation clarification.
- (b) **BTC pro-forma hedge.** Literal: "the pro-forma BTC hedge exits at the same time" (as the delayed / settled leg exit). Code: B(t_x_eff) by S-5.2 + the gap rule (a); BTC HALTED at t_x_eff -> invalid `btc_exit_halted` (no BTC waiting, which would desynchronize the hedge from the leg); BTC entry proxy h_B(t_e) missing -> invalid `entry_proxy_missing` (S-4.4 entry rule applied to the hedge entry); BTC exit proxy missing -> 25 bps + 3 x slip, flagged `btc_exit_proxy_fallback`. Literal alternative: the BTC hedge is pro-forma (never executed); S-5.4 / S-5.5 make a halted B(tau) invalid only at t_e, and B(t_x_eff) as a reference price (the open of the BTC 1m bar at t_x_eff, S-5.2) is computable even while BTC is halted, so the literal text gives no invalid cause for a halted BTC at the exit. Classification: **normative amendment required - user decision** (`btc_exit_halted` adds an invalid cause outside S-5.5). Interim: the current conservative rule (invalid) stays in code until the user rules.
- (c) **"A label reaches a terminal event".** Code: the label reaches its instance's cessation iff (i) the instance's `last_trade_ts` <= the scheduled t_x (the leg is still held at cessation), or (ii) the leg is HALTED at t_x and no executable 1m bar of the instance exists before cessation (`last_trade_ts` < window end). Then the classified `TerminalEvent` of that instance is required (missing -> ValueError, the caller must classify); B / C -> invalid `terminal_not_reconstructible`; A -> exit at (settle_ts, settle_price), taker fee, no spread / slippage. A settlement at or before t_e -> invalid `terminal_at_or_before_entry`; at or after the window end -> invalid `no_executable_exit`. If the instance has not ceased (or ceases at/after the window end) and no executable bar exists before the window end -> invalid `no_executable_exit`. Classification: implementation clarification.
- (d) **Window end.** Literal: "t_x at or past the window end: no label"; a halted exit with no executable bar "before the window's terminal unwind" is invalid; the terminal unwind is "at the last reference minute before the window's end". Code: scheduled t_x >= end -> None; a waiting halted fill must have its fill time (bar close) strictly before the end (i.e. at the latest the last minute before the end) - a fill exactly at the end is invalid (`no_executable_exit`). All frames are trimmed to timestamps < end before use. `label_known_at` = t_x_eff + 1 min may equal the end. Classification: implementation clarification.
- (e) **Guard spans.** `guard.check_outcome_window(lo=t, hi)` (half-open): always [t, min(t_x + 1 min, end)) before any read (for a None label: [t, end), no data read); [t, end) before a halted wait; [t, tau + 60 min + 1 min) before an exit gap search; [t, settle_ts + 1 min) for an A settlement. Classification: implementation clarification.
- (f) **Funding window (S-5.3, S-5.5, S-2.6).** Settlements tau_k in (t_e, t_x_eff] of the leg's (BTC's) current instance at t, using records with `known_at` <= `label_known_at`. Missing settlement = the DEC-29 adjacent-interval gap rule (`intervals.u3_gap`) over the sequence from the head record (last record <= t_e of the instance, invalid ones included as timestamp anchors) to the last record <= t_x_eff, plus the tail t_x_eff - last <= its nominal interval + 60 s (Stage 0 `funding_ok` semantics); no head record -> missing. Any invalid record or non-finite rate in the window -> `funding_invalid`. r_k = raw rate; M(tau_k): record mark (finite > 0) -> R4 mark 15m close ending at tau_k -> R3 last-price 15m close ending at tau_k (unusable closes skipped) -> else invalid `mark_missing` (S-5.5 "required reference price missing"). Classification: implementation clarification.
- (g) **beta-hat missing.** S-5.2 requires >= 500 joint hourly observations; S-5.5 does not list "beta missing" as an invalid cause. Code: invalid `beta_missing` (no value can be computed without inventing one). The spec has no literal fallback; using the prior 1.0 (or any other value) would be a new rule. Classification: **normative amendment required - user decision** (adds an invalid cause outside the S-5.5 list; the S-2.3 gates (U1 60 d) make it rare for eligible candidates). Interim: the conservative rule (invalid) stays in code.
- (h) **Halted exit without a fill-time proxy.** max(h_fill, 25 bps) with h_fill missing = 25 bps, 3 x slip; flagged `exit_proxy_fallback` in addition to `halted_exit`. No current instance at t (leg or BTC) -> invalid `no_instance`. Classification: implementation clarification.
- (i) **Notes (fix round 1).**
  - Terminal rule (c)(i) uses the retrospective instance end `last_trade_ts`, consistent with S-2.2 (labels are outcomes). Because the end is only known at `end_known_at` = `last_trade_ts` + 7 d, a label whose t_x lies within ~7 d of the window end can be classified as reaching cessation (terminal) although the end would not yet be known at the window end; the data are all before the window end (S-1.5 holds), only the knowledge of permanence comes from after it.

- (g) **E_M details.** Touch L = P(t_e) (1 - d h-hat(t)) (h-hat is proportional); trade-through quantities (base units) are compared with the order at `usd_per_unit` = E_ref = 10,000 USD per book unit in L-norm (as the liquidity cap, §14); one maker fill per aggTrade timestamp at L, booked at that timestamp, maker fee, no spread / slippage, reference mid = L (so C_exec >= 0 and the spread capture shows in PR, not as a negative cost); h-hat(t) missing -> no limit can be posted, taker at t_e; the remainder fills by the taker rules at t_e + 30 min (an entry remainder that cannot trade leaves a partial entry). Maker-first applies to every non-forced leg order (decision exits, neutrality closes, drift / cap reduces, entries); forced exits and every hedge trade are taker. Adverse move: -d (P(m + k) / L - 1), m = the first minute >= the fill time, k = 5 / 30 / 60 min, P without the gap rule, None when missing or past the window end. A maker window is cut at the terminal unwind: no maker fill at / after end - 1 min and a remainder due then is not traded (`order_cancelled_at_unwind:<pid>` in `integrity`; the unwind closes a held position, an entry stays partial). Alternatives for the quantity scale: E = 265 USD (the deployment layer), or book-unit quantities without scaling (E = 1 USD, almost always fully filled); the scale decides how much of an order fills as maker. Classification: **normative amendment required - user decision** for the E_ref scaling (E_M is secondary, S-6.3, but it is a reported result); the rest is implementation clarification (the maker reference-mid convention is borderline).
- (h) **Funding in the book.** Each settlement of a held instance is booked at its time with the S-4.6 mark chain (`refs.FundingSchedule`, shared with the labels); an invalid record or a missing mark books nothing and is reported (`funding_invalid:` / `mark_missing:` in `integrity`); the DEC-29 missing-settlement test runs per closed episode over (first fill, last fill] (`funding_missing:<pid>`). The engine never invalidates a run for funding: the K8 rate test is Task 16's. Classification: implementation clarification.
- (i) **Positions.** A leg belongs to the instance current at its entry decision (E10); average entry = quantity-weighted executed entry price (incl. spread / slippage); the terminal check runs at the retrospective instance end (`last_trade_ts`, as AMB-10 (c)/(i)) - A: at the official settlement time if still held then, B / C: at the observed cessation; an entry filled after an A settlement time raises. The BTC hedge is one position per non-zero episode (a sign flip in one trade keeps the episode); a BTC instance change while hedged raises. Classification: implementation clarification.
- (j) **Terminal unwind.** At end - 1 min: P(end - 1 min) (the gap search cannot leave the window), taker with h_fill (25 bps + 3 x slip if missing), legs then the hedge. Halted then -> INVALID RUN (an executable bar opening at or after end - 1 min closes at or after the end). Decisions run only when t + 15 min < end - 1 min; an E_M remainder due after the unwind is cancelled (`fill_after_unwind_cancelled`) and the unwind closes the position. Classification: implementation clarification.
- (k) **Decision inputs.** Gates, h-hat(t), beta-hat(t), the 24 h quote volume, the gated candidate rows and the S-7.3 staleness flag come from an explicit provider (`DecisionView`); the engine asserts PIT on every gate row (`universe.assert_pit`) but cannot verify the other fields. Wiring the provider (universe.gates, spread, beta, features, the fold model per decision) is the runner's job. Only L-norm runs here (E = 1, E_ref liquidity cap); L-265 / L-10k are Task 17. Classification: implementation clarification.

## AMB-20 - Terminal unwind minute without a reference price (not halted) (Task 14b fix round 1)

- Spec: S-1.5 ("the terminal unwind at the last reference minute before the window's end"), S-8.1, S-5.2 (P(tau) = the open of the 1-minute bar starting at tau, fallback the 15-minute bar starting at tau), S-5.4 (data gap: "use the first 1-minute bar within 60 min after tau. If there is none, the label is invalid"; halted exits wait; none by the unwind -> INVALID RUN), S-4.4 ("if the required reference price itself is missing, the existing invalid / gap policy applies ... No price is invented").
- Case: at end - 1 min the instrument is NOT halted (it traded in the previous hour), but the 1-minute bar starting at end - 1 min is missing (a data gap); the 60-minute gap search cannot leave the window (S-1.5), so there is no reference price inside the window.
- Options: (i) INVALID RUN (no price is invented; the gap rule has no bar before the end); (ii) fill the unwind at the last usable non-halted minute <= end - 1 min (the latest 1-minute bar with a usable open before the end, i.e. that leg's unwind moves earlier); (iii) other, e.g. the open of the last 15-minute bar, or a gap search backwards before the end.
- Code (interim, conservative): (i) - `INVALID RUN — no executable exit before the window's terminal unwind`, `invalid_detail` "no reference price at the unwind minute (data gap, not halted; AMB-20)" (a halted leg reports "halted at the unwind"). Test: `test_unwind_minute_data_gap_is_invalid_not_halted`.
- Classification: **normative amendment required - user decision**. **PRE-RUN BLOCKER: under (i) a single missing 1-minute bar at end - 1 min of any held instrument invalidates a whole W_DEV / W_HOLD run; the user must decide before any book run.**

## AMB-21 - Book accounting: asset key, episode walk, K10 tolerance, P6 "mean daily net" (Task 15)

- Spec: S-8.1-S-8.4, K10 (§16), S-13.2 P5 / P6 / P11, §12, E10. Code: luna/v7/accounting.py.
- (a) **"Asset".** Literal: S-8.3 "a leg asset's position", "the same (asset, side)"; S-8.4 "N_a"; E10: instances are separate instruments. Code (controller ruling, fix round 1): episodes and clusters are per instrument instance (an episode is a position of one instance; two instances of one symbol cannot chain within 72 h in practice, so cluster / P4 / P11 counts are the same under either key); **N_a (S-8.4, P5) and the §12 per-asset ρ / concentration are keyed by SYMBOL** (a relisted symbol's instances are pooled into one N_a), which is the conservative reading for P5's top-1 / top-3 shares and matches the constructor's "asset" (constructor.py). Non-chosen option: N_a per instance (a relisted symbol split into two N_a entries, lowering the measured concentration). Classification: implementation clarification (the conservative reading is implemented).
- (b) **Episode walk.** Instrument j = (role, symbol, instance): the leg book and the BTC hedge book are separate instruments (BTC is never a leg in practice). Events of j: its fills and its `positions` tick rows, ordered (ts, tick before fill, booking order); q(e⁺) = the engine's `q_after` (the engine books an exit of ≥ (1 − 1e-9)|q| as a full close, so −Σ dq·p(f) can differ from the event sum by ≤ ~1e-9 of that fill's notional; `PR_fills` is reported as a diagnostic, PR is the event sum, which is what the daily price column books). An episode is a maximal non-zero constant-sign stretch of the summed leg position of j (overlapping position ids of one instrument would merge); β̂_episode = the `beta` of its opening fill. Fail closed (`ValueError`): a missing / non-finite / ≤ 0 B(e) at any event of an episode (fill `btc_ref`, tick `marks.btc_mark`; no carried or interpolated BTC price), a missing β̂_episode, a leg fill reversing the sign, a tick whose quantity differs from the book before that timestamp's fills, a non-flat end, a position id in two episodes, funding of an unknown leg position id, a held position without a `positions` row at a 15-minute tick (a `marks` row). A fill whose `q_after` differs from q + dq by more than the engine's 1e-9 close clamp is recorded in `Ledger.q_breaks` and fails K10 (fix round 1). Classification of the rest: implementation clarification.
  - **Missing B(e) (fix round 1).** A missing BTC reference at any event of a held leg (a fill's `btc_ref` None, or `marks.btc_mark` None at a tick, e.g. no BTC mark bar and no last-price bar at that tick) makes `account` raise: the run cannot be accounted, an unspecified run-level failure. Options: (i) fail closed (interim code); (ii) use the engine's mark -> last-price -> stale chain for B as for every other instrument's tick marks (AMB-19 (e)); (iii) treat it as a K10 / integrity failure (INVALID RUN) explicitly. Classification: **normative amendment required - user decision. PRE-RUN BLOCKER: under (i) one missing BTC mark at a tick while any leg is held makes a whole W_DEV / W_HOLD book unaccountable.** Test: `test_invalid_run_refused_and_inputs_checked`.
- (c) **K10 / daily-table tolerance.** K10's second clause "PR ≠ the daily-table price column" is checked with the same 1e-9 × Σ|qty · ref_mid| tolerance (float summation order makes exact equality unattainable), both in total and per day (the per-day price is recomputed from the events with the engine's day boundaries: a fill's price event and costs belong to the day with start ≤ ts < end, the unwind fill to the last day; a tick's price event and a funding settlement to the day with start < ts ≤ end, AMB-19 (f)). `daily_ok` (S-8.1) checks the engine's funding / fees / spread_slip / price per day against the recomputation, net = funding − fees − spread_slip + price = the equity change per day, and NET = the window's equity change, same tolerance. K10 also requires the summation by parts: no `q_breaks` and |−Σ dq·p(f) − PR| within the tolerance (fix round 1). `daily_ok` is not part of `k10_ok`; **Task 16 must map a `daily_ok` failure to the S-13.4 "integrity" check (INVALID RUN).** Classification: implementation clarification.
- (d) **P6 "stressed mean daily net".** Code: `mean_daily_net` = the mean over the window's daily rows of the daily table's net column, in book units (L-norm, E0 = 1); `mean_daily_return` (mean of net_t / E_{t−1} on the cost-shifted equity path) is also provided. The stressed ledger keeps every fill's ts / qty / ref_mid and every funding flow; only fee × 1.5, slip_cost × 1.5, spread_cost × 3.0 change (the fallback 25 bps and S-5.4 stressed-exit spreads are inside `spread_cost`), and the daily table's costs, net and equity are shifted by the extra costs. The equity path that drives risk (daily-loss pause, drawdown kill) and sizing is NOT re-simulated ("the same executed book"). Alternative: P6 on the mean daily return r_t (S-13.1 definition), which can differ in sign from the mean daily net only in edge cases. Classification: implementation clarification (borderline). **P6, P10 and S-10.7 ("mean daily net ≤ 0") all use `mean_daily_net`** (the same reading everywhere); `mean_daily_return` is reported only.
- (e) **P11 details.** n_clusters = clusters with ≥ 1 closed episode (in a valid run every episode is closed by the unwind, so all clusters count); Top_m = the m clusters with the largest strictly positive ρ_c, ties broken by (asset, side, first start); fewer positive clusters than m → all of them; m = max(3, ⌈n / 20⌉) in integer arithmetic. `net_trim(led, m)` also serves the §12 report m ∈ {1, 3, 5, 10}. Classification: implementation clarification.

## AMB-22 - Statistics, selection and verdict conventions (Task 16)

- Spec: S-10.6, S-10.7, S-13.1-S-13.4, §12, §16, EC-2, EC-11. Code: luna/v7/stats.py, luna/v7/selection.py, luna/v7/verdict.py.
- (a) **Bootstrap seed.** Literal: "seed fixed and recorded". Code: `stats.SEED` = the frozen V7 seed (`FROZEN.search.seed` = 20261014); every CBB index matrix is `default_rng(seed).integers(0, T, (B, k))`, the same seed for each ℓ and each test; the seed and B are carried in `CBBResult` / `Choice`. Classification: implementation clarification.
- (b) **q₀.₉₅ of the bootstrap distribution.** Not fixed by the spec. Code: the empirical quantile `inverted_cdf` (the ⌈0.95 B⌉-th order statistic of θ̂* − θ̂). Alternative: linear interpolation (numpy default); the difference is below one order-statistic gap. Classification: implementation clarification.
- (c) **Holm with a voided member.** Literal: "Holm–Bonferroni across exactly this family of 6" and "an invalid secondary arm voids only its own comparison". Options: (i) keep m = 6, the voided member ranked as a non-rejection (p = 1, reported "unavailable", adjusted value None); (ii) drop it and adjust over m = 5. Code: (i) (keeps "exactly 6", conservative; never changes S-13.2 / S-13.4). Classification: implementation clarification.
- (d) **Sharpe and the "Lo / Newey-West adjusted value".** Code: plain Sharpe = mean / std (ddof 1) × √365; the adjusted value replaces the variance with the Newey–West HAC long-run variance (Bartlett weights 1 − k/(L+1), autocovariances normalised by T − 1 so that L = 0 reproduces the plain value), lag L = ⌊4 (T/100)^{2/9}⌋ (Newey–West 1994; T = 365 gives 5), × √365. Not chosen: Lo (2002) q-period scaling with autocorrelations up to lag 364 (unstable on one year). Report only (P9 uses the plain value). A zero variance gives NaN (P9 fails). Classification: implementation clarification.
- (e) **W_DEV integrity.** Any `BookRun.invalid` among the 9 required runs (either S-5.4 string) → `INVALID RUN — historical terminal execution not reconstructible` (exact S-10.6 text) listing every invalid run. A required run whose ledger fails `accounting.k10_ok` or `accounting.daily_ok` → `INVALID RUN — K10 / accounting integrity failure` (S-13.4 / K10; my wording). A missing required run raises (fail closed). Reference arms (A0-V5, TS) may be passed and are only reported. Classification: implementation clarification.
- (f) **S-10.6 choice.** LBs are in daily-return units (S-13.1 r_t), 1 bp/day = 1e-4. Order: the A3 family is chosen iff max LB(A3) − max LB(A2) ≥ 1 bp/day (inclusive); within the chosen family, the tie set is every horizon with LB ≥ (family max − 0.1 bp/day) (inclusive, measured against the maximum, not chained), and the longest horizon in it wins. Classification: implementation clarification.
- (g) **W_HOLD required runs and P1 under E_M.** Literal: "a required arm (ML\*, A0) ...", "P1 fails under E_T but holds under E_M". Code: ML\* and A0 are required under both E_T and E_M (the E_M runs are needed to separate "no viable edge" from "maker-dependent"); any of the four invalid → INVALID RUN. P1 under E_M is the S-13.1 IUT of ML\* E_M vs A0 E_M (same execution model on both sides). Alternative: E_M runs not required (an invalid E_M run would make P1(E_M) "fails"), or A0 under E_T as the E_M baseline. Classification: implementation clarification (borderline; it only matters when an E_M run is invalid while the E_T runs are valid).
- (h) **P4.** "gross" = the leg gross notional at the 15-minute tick (`marks.gross_legs`, hedge excluded), compared with the marked equity at the same tick (≥, inclusive); a quarter-hour belongs to the UTC day of its tick (00:00 opens a day; the last day ends at the unwind and has < 96 ticks). Classification: implementation clarification.

- (j) **P8-classifier ECE.** Rows sorted by P̂ (stable), split into 10 equal-row-count bins (`numpy.array_split`; tied P̂ values may straddle a bin edge), date-equal weights summing to 1 over all rows; ECE = Σ_bins |Σ_i w_i (y_i − P̂_i)| (= Σ W_b |ȳ_b − p̄_b|). Alternative: weighted-quantile bin edges. Classification: implementation clarification.
- (k) **Other verdict conventions.** P3: the drawdown runs over the 15-minute marked equity plus the final post-unwind equity; "drawdown kill" = any decision row `killed` or any fill with reason `kill`. P8-primary: unclipped date-equal-weight OLS slope (NaN for a constant ŷ_cal → fails); band inclusive. P2: C_exec / F_net only for F_net > 0. Classification: implementation clarification.

A `daily_ok` failure is an S-13.4 integrity failure (AMB-21 (c) resolved). Classification: implementation clarification.
